P0

Stop the bleeding

before any public URL

Nothing here is a feature. These are the five things that make it safe to have users at all. Today the app is invisible when it breaks, unlimited when it is abused, and has never been deployed to its own front end.

1. Global spend cap, kill switch, alerting

BlockerS

Every limit is per user, and anonymous sign-in is free and un-captcha'd. One script minting accounts multiplies the ₹114/day ceiling without limit. There is no project-wide cap, no way to turn the relay off, and no alarm — the relay's own docblock admits it. Add a daily project ceiling inside claim_relay, a RELAY_DISABLED env kill switch, and an alert when spend crosses a threshold.

2. Turn the lights on

BlockerXS

lib/telemetry.ts is a complete no-op with no Sentry DSN and no PostHog key, so a white screen on a ₹10,000 Android is an uninstall nobody hears about. Both are free. This is a 10-minute task that has been open for weeks and it gates every decision after launch.

3. Make CI actually run

Parallel-safeXS

.github/workflows/ci.yml exists and has never run once. 2,800 tests that only execute on one laptop are not a safety net. Same job, plus check-bundle-secrets.

4. Apply 0014, and add org_id while the tables are empty

SequencedS

Verified live: concept_state.answer_observations returns 42703 — 0014 is written but not applied. And student_state, relay_usage, prepared_class and usage_event have no tenancy column at all. Right now that migration backfills zero rows. After launch it is the migration nobody wants to run, on tables full of children's answers.

5. Actually deploy the front end

BlockerXS

vercel.json is configured and npx vercel deploy --prod has never been run. There is no linked Vercel project. The Edge Function is live; the thing students open is not.

P1

Web MVP — take users

the launch

A student finds Curie, understands what it is in ten seconds, signs up, and has a class. Everything here is web-only and none of it waits on Play Store, on-device models, or the STT research.

Riso Pop re-skin — one brand instead of three

Parallel-safeS

The audit found the UI system is better than the docs claim — real tokens, a type scale, a tested icon set, a four-state vocabulary. The problem is brand, not UI: two unrelated marks (an atom logo and a penguin mascot) across three palettes, with a leftover Google-Stitch indigo still owning the first thing a student sees. Generated token files are ready; class names are unchanged, so no screen has to be rewritten.

The website that does not exist

Parallel-safeM

There is no landing page anywhere in the repo. For a D2C product where the parent is the buyer and the teenager is the user, one page has to convince both. Plus privacy policy and terms, which the DPDP work needs anyway.

Pre-render the narration — the big cost lever

SequencedM

Narration is re-synthesised for every student, every play. Render it once at prep time and store it beside lesson.json. tools/record-class already exists and NarrationManifest is a supported rung of the voice ladder — it is populated for one lesson out of fifteen. This works on the web with no on-device anything.

Authored replies in the lesson format

SequencedM

Her spoken answers are generated and synthesised live on every judged answer. If the class carries its own replies, they get recorded with the narration and cost nothing per play. Needs a lesson-format change and a re-author pass over the committed lessons.

Doubt tutor: through the relay, screened, capped

SequencedM

Your headline feature is dev-only today, puts a real vendor key in browser code, bypasses the meter entirely, and its replies reach a child unscreened. Route it through the relay, screen the output with speakSafely like every other path, meter it, and cap raised hands per student per day so it is a known cost rather than an open one.

DPDP consent and the age gate

BlockerM

India's DPDP Act requires verifiable parental consent for under-18s. Identity is anonymous-at-boot with no age gate beyond a class setting. This was meant to be decided before auth was built; it was not, so it now costs a change to a screen that exists. It blocks the public launch and every school conversation after it.

Content: past Class 9–10 science

Parallel-safeM

15 lessons against 1,099 mapped topics, all one subject band. Preparing the entire catalogue costs about ₹17,800 once, ever — money is not the constraint. Quality review is: there is no quality score, no version, no rollback, and a wrong cached class is permanent and invisible.

Cost at the end of P1: roughly ₹17–30 per student-hour on web, down from ~₹158. Not ₹5 — ₹5 is an Android number and always was. Ship with a per-student daily cap so the worst case is bounded and known.
P2

Android — and the ₹5 target

starts during P1

This phase starts in parallel with P1, because Play review is a queue you want to be standing in early. But it cannot finish first — the build cannot even be uploaded today.

Make an uploadable build exist

BlockerM

There is no release signing config, no keystore, minifyEnabled false, versionCode 1. npx cap sync android runs clean, but assembleDebug was never verified in CI and the last known-good build predates the 23.5 MB onnxruntime wasm entering the bundle. No AAB can be produced right now.

Get the models into the app at all

BlockerL

This is the finding that changes the plan. content/models/ is gitignored and absent, fetch-speech-models.mjs is in no build script, and allowRemoteModels is false — so on-device synthesis returns null and every line falls through to cloud Aura. Android costs exactly what web costs today. The ~306 MB also exceeds Play's 200 MB limit, so it must be a download-on-first-run, which is its own install-conversion problem on cheap phones.

On-device Hinglish speech recognition

Parallel-safeL

You chose to solve this properly, and it is the right end state — cloud STT alone is about ₹4.5 of the ₹5 budget. Moonshine-tiny is English-only and returned an empty string on real Hinglish. Candidates to evaluate on a 4 GB Mali phone: IndicWhisper, AI4Bharat IndicConformer, Whisper-small multilingual. Run this as its own workstream, not on the launch critical path — the web MVP uses the cloud ear regardless.

Play Console, store listing, review

SequencedS

$25 one-off, plus privacy policy, data-safety declaration and the DPDP children's-data answer from P1. Start the account now; the queue does not care that the build is not ready.

Cost at the end of P2: about ₹17/student-hour with models shipped and the ear still in the cloud, then ₹5 or below once on-device STT lands. Note the repo's ₹4 route assumed the learner model resolving 72% of answers — that route does not work as drawn, because no committed lesson's ask carries options.

P3

LMS — the second person

after users exist

Curie already has a real single-player LMS — placement test, study plan, quiz, plan adaptation, streaks, achievements, history, notes. It works. What it has is no second seat of any kind, proven three ways: no screen addresses anyone but the student, no RLS policy grants a read to another user, and no tool reads learning data with the service key.

The server-side fold

BlockerL

Everything in P3 depends on this one thing. The learner model lives only in localStorage and reaches Postgres as one opaque jsonb blob under last-write-wins, in a table the student can also delete. concept_state and learner_model have no reader and no writer. A parent cannot be shown a model that lives on their child's phone. This also unlocks cross-device continuity and cohort signal.

Parent view first, then teacher

SequencedM

For Indian K–12 the parent is the buyer, so the parent view is a revenue feature, not a reporting one. Tenancy (0005) exists and is genuinely load-bearing — every ledger insert depends on it — but it cannot express a guardian today. Once the fold is server-side, a parent view is a policy change rather than a migration.

Close the loop in the classroom

Parallel-safeL

The brain is two-thirds real: a working BKT posterior with slip/guess over 5,079 nodes, and a fold that reaches the persona, the doubt tutor and the planner. What is missing is the controller — ClassRoom.tsx still decides every ask, every rung and every hint, chooseAsk has no caller, and asks carry no options so the advance gate always opens. This is what turns a very well instrumented lesson player into an adaptive tutor.

Entitlement and payments

SequencedM

There is no plan, tier, credit, entitlement or payment code anywhere in the repo. Monetisation is not "add Razorpay" — it is that the gate deciding who may spend does not know who is paying. That is a relay and schema change, and it is cheapest before payments exist.

Where this can still go wrong

ranked
  1. The models never fit. 306 MB against Play's 200 MB cap, on phones where a 300 MB download is a real decision. If download-on-first-run converts badly, the ₹5 target goes with it and Android is just a web app in a shell.
  2. Hinglish STT stays unsolved. It is the only item on this plan that is a research question, not an engineering task, and roughly ₹4.5 of the ₹5 depends on it.
  3. A wrong class is permanent. No quality score, no version, no rollback. saveable() refuses four things and none of them is "is this correct".
  4. The public bucket is the library. Every kept class is fetchable with no session and no meter. It is simultaneously your moat and an unpriced egress bill.
  5. Prices were never pasted. tools/sql/model_price.sql is applied by no script, by design. It is not verified that anyone ever ran it — so the cost reports may quietly read unpriced.
  6. Building for a buyer nobody has met. Zero students so far. Every number in this plan except the costs is an assumption until P1 ships.
