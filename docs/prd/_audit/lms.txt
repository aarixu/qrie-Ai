== RISKS ==
  - [critical] ONE ANSWER ON A MULTI-OUTCOME BEAT COMPOUNDS BELIEF ACROSS THE PREREQUISITE CHAIN. foldAnswer loops over event.outcomeIds and calls applyEvidence once PER outcome, each time rebuilding `before` from the states the previous iteration already moved — so propagation is applied N times for one answer.
      packages/learner-model/src/fold.ts:214-269. Measured in this audit against a real GraphIndex: a single CORRECT answer on a 7-node prerequisite chain leaves n0=0.9607 (obs=7), n1=0.9594, n2=0.9571, n3=0.9523, n4=0.9417, n5=0.9130 — six of seven above the 0.75 'settled' line in confidenceCoverage, from one answer. A single WRONG answer on the same beat leaves n2..n6 at 0.0200, the FLOOR in mastery.ts:23. Compare the honest single-outcome case: 0.5151 / 0.5275 / 0.5499 / 0.5907 / 0.6650 / 0.8000. The unassisted branch is safe (it folds a one-node map), so the primary metric is unaffected — but `mastery` is what masteryView hands to the persona, the doubt tutor's secure/shaky marking and learnFromQuiz's gap detection. Committed content is currently capped at 2 outcomes per ask beat (6 of 22 asks), which limits the blast radius today; class-prep generates `checks` lists live with no cap in the prompt (packages/class-prep/src/prompts.ts:84) or the validator (packages/lesson-format/src/validate.ts:261), so a live-prepared class can produce a 5-outcome ask and floor five outcomes off one misheard Hinglish answer.
  - [critical] THE LEARNER MODEL EXISTS ONLY IN ONE BROWSER'S localStorage AND THE LEDGER BEHIND IT IS PURGED AT 90 DAYS.
      apps/classroom/src/lib/learnerModel.ts:31 is the only store.   - [high] THE FOLD CURSOR RUNS ON THE DEVICE CLOCK, AND A BACKWARDS CLOCK JUMP SILENTLY DROPS A WHOLE SITTING'S EVIDENCE FOREVER.
      FoldCursor.at is documented as 'the SESSION'S started_at — a server clock' (packages/learner-model/src/types.ts:93-100), but on the device it is Outbox.session.startedAt, stamped by `new Date().toISOString()` at apps/classroom/src/stores/ledger.ts:160 — learnerModel.ts:22-23 admits this. behindCursor (fold.ts:131-138) skips anything at or behind the cursor, so if an NTP correction moves the clock back between two sittings, every event of the later sitting is skipped.
