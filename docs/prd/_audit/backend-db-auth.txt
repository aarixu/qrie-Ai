  - [medium] student_state is a full-write table with no org_id, holding the student's name, class, notes and ~195 KB belief blob, and no retention
      Its policy is `for all` with both using and with check (0001:21-25) — 0013:12-15 says so explicitly and calls it 'deliberately stricter' by contrast.   - [medium] Usage attribution is entirely client-controlled
      sessionOf reads x-session-id from a header, or ?session= from the query for speech (handler.ts:118-123). record_usage inserts it with no check that the session belongs to p_user (0008:83-89), and usage_event.session_id is deliberately not a foreign key (0008:22-24). So any student can attribute their spend to any session id, including another student's. session_cost and cost_per_student_hour are computed off exactly that column. Harmless while nobody is billed; a direct fraud channel the day a credit is priced per learning minute.

== THINGS THE AUDIT MISSED ==
  + Direct PostgREST writes bypass the relay meter completely, and student_state is an unbounded jsonb write surface. The audit's framing — 'every limit is per-user' — assumes all spend flows through the relay. claim_relay runs only inside admit(), which runs only inside handleRelay. The client writes student_state, learning_session and ledger_event straight to PostgREST with its own JWT, never touching the relay, so those writes are unmetered, uncounted in usage_event and unbounded by UNITS_PER_DAY. student_state's policy is `for all` with using and with check on auth.uid() alone — no constraint on key, on value size, or on row count — so one free anonymous identity can write arbitrary jsonb into the project's Postgres indefinitely. That is a second denial-of-wallet channel against a free-tier database, distinct from the relay one the audit describes.  [packages/relay/src/gate.ts:225 `const claim = await gate.ledger.claim(...)` inside admit; packages/relay/src/handler.ts:205 the only admit call site; apps/classroom/src/lib/supabase.ts:83-91 `db.from(TABLE).upsert({ user_id, key, value, updated_at }, { onConflict: 'user_id,key' })`; apps/classroom/src/lib/ledgerSync.ts:296-301 direct `db.from('ledger_event').upsert(...)`; supabase/migrations/0001_student_state.sql:21-25 `for all using (auth.uid() = user_id) with check (auth.uid() = user_id)`]
