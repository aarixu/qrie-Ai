## SETTLED — do not re-open

These were decided with evidence and are not open questions. Writing them down
because one of them was re-opened by me on 2026-09-02, which cost an hour.

Re-opening one on a hunch is the cost this table exists to prevent. New
measurement is not a hunch: the speech row was reversed by it on 2026-09-14,
and the note under the table says what measured what. A row whose reasoning has
been overturned is the most expensive kind of line in this file, so it gets
rewritten rather than defended.

| Decision | When | Why it stands |
|---|---|---|
| **Gemini direct** for the brain, with NCERT context caching | 2026-08-30 | Build order item 4. OpenRouter was always the stopgap. |
| **Self-hosted TTS, cloud ear** | 2026-08-30, revised 2026-09-14 | Reversed by measurement; this read "On-device STT and TTS". The reasoning is under the table. |
| **STT must be multilingual** | 2026-08-31 | Moonshine is English-only and these students speak Hinglish. Measured: an English-only model returned eight words from twelve minutes. |
| **Synthesise during prep, never live** | 2026-08-31 | Measured 0.7x realtime on a 4 GB Mali phone. |
| **Models bundled in the app** | 2026-08-30 | Kills the 255 MB first download; warmed at app start while the student picks a topic. This is why Phase 2 must come before Phase 3. |
| **2D Rive avatar** | 2026-08-30 | 250 KB against 4.5 MB, and no uncanny valley. The code-drawn penguin holds the seam until a .riv exists. |
| **The recording is a SPINE, not a session** | 2026-08-29 | Narration plus canvas actions are cached; the live tutor fills the personal parts per student. |
| **Duolingo-school UI, not invented** | earlier | Copy established edtech language. |

**The speech row, and why it was reversed.** It was headed "On-device STT and
TTS", dated 2026-08-30, and the reason it gave was "The whole ₹1.41/student-hour
case is client-side offloading. Cloud speech is temporary scaffolding, so which
cloud vendor it uses is not worth arguing about." Measurement inverted both
halves of that.

₹1.41/hr is the ANDROID case, and it is still untested. The launch vehicle is
the web, whose measured base is ₹164/student-hour and ₹9.90 a cached class
(`node tools/measure/model-cost.mjs`, 2026-09-13). Speech is 86% of that and
the only part paid in cash, so the speech path was the whole cost question and
never scaffolding. Serving the voice ourselves — `tools/speech`, Piper on CPU
at 10.8x realtime, 355 ms to the first line against the vendor's 360 ms,
measured 2026-09-14 — would take a cached class to ₹1.40 and the hour to about
₹23. Those two figures are CONDITIONAL and are not what anything costs today:
the code is done and measured, and it does not run until a Piper voice is
chosen from the three Hindi ones and a publicly reachable host is provisioned
for `CURIE_SPEECH_URL`. Both are Aarav's, and neither has happened.

The ear STAYS in the cloud, at ₹0.27 a class. No self-hosted or on-device
Hinglish ear exists that is not worse than useless: `whisper-tiny.en` invented
fluent English out of Hinglish and has had no caller since 2026-09-14,
`faster-whisper` measured 0.30x realtime and garbage at avg logprob −0.79
(`tools/speech/README.md`), and the relay asks the vendor for `language=multi`
(`relays.ts:264`). On-device TTS survives only as a client-side latency layer
in `lessonVoice.ts`. This narrows the next row down rather than contradicting
it — STT must still be multilingual — and it is why PHASE 3 is the Android
track and not the launch path.

### Decided 2026-09-02 (evening) — BUILT, MEASURED, and ON

**Pictures are found before they are generated.** Aarav's call: generating an
image is the LAST resort, not the first. In order — draw it, take it from the
icon/asset library, take it from the WEB — and anything taken from the web is
shown to a model once and asked "is this actually the thing that was needed?"
before it reaches a board. Image generation only when nothing else can supply
it.

Why it matters: a generated picture is the one most likely to be wrong in a way
a student notices. Cost is not the argument. This line read "the most expensive
thing in a class (₹5.75 against ₹1.51 for a drawn diagram, per class-prep's
README)" until the billing was settled on 2026-09-13: a picture is charged as
1,120 output tokens on `gemini-3.1-flash-image` rather than per image, which at
$2.00 per million output tokens (`tools/sql/model_price.sql:60-62`) is about
₹0.215. That is the price list applied to a token count, not a row off the
measured class's wire — that class generated no pictures at all, both its
visuals being canvas diagrams from the artist, as the closed-loop plan records.

The ₹5.75 was never in that README, and it was not a guess. It is the original
measurement, still at `liveClass.ts:38` — "Measured on a half-cut kidney: 11s
and about Rs 5.75, against Rs 2.25 for the whole class without one" — taken in
the OpenRouter era, and `tools/sql/model_price.sql:34` carries it forward as
what a credit price should assume until the billed row is confirmed. What moved
the number is the billing path and not better arithmetic: an OpenRouter charge
per image became Vertex charging the same picture as output tokens.

Which means the ₹1.51 comparison is mixed vintage and understates the gap. That
figure is OpenRouter too (`packages/class-prep/README.md:63`); in the same
2026-09-13 Vertex run the two artist calls cost ₹2.07 and ₹2.70 — the two prep
rows of 648 and 677 prompt tokens in `tools/measure/last-class.json`, which is
the artist's signature per `gate.ts:69`. Like for like on today's billing, a
drawn diagram is ₹2.1–2.7 and a generated picture about ₹0.215: ten to twelve
times cheaper, not seven. The most expensive thing in a class is speech, 86% of
the bill — ₹8.51 of TTS in a ₹9.90 cached class, measured 2026-09-13. The
breakdown is "Where a class's money actually goes", under PHASE 6.

**What is built** (`packages/class-prep/src/fromWeb.ts`, `commons.ts`):

- `findOnTheWeb` searches, filters by licence BEFORE downloading anything,
  fetches up to three candidates and shows each to a vision model once. An
  unreadable verdict is a NO — this is the one parse in the pipeline that fails
  closed, because the alternative is an unverified image on a child's board.
  With no eyes configured the rung is skipped entirely rather than trusted.
- Only CC0, public domain, CC BY, CC BY-SA and Commons' "No restrictions" pass.
  NonCommercial and NoDerivatives are vetoed BEFORE the allow-list is consulted
  ("CC BY-NC-ND 4.0" contains "cc by"). A licence the search did not report is
  a refusal. A class is cached and served publicly, so this is a takedown risk
  against a children's app rather than a cosmetic one.
- `createCommonsSearch` is the search: Wikimedia Commons, **no API key**,
  every file openly licensed and stating which.
- The prep report says which rung answered (`from: 'web' | 'generated'`),
  quotes what the web offered and why it was refused, and carries the source
  page plus licence of every found picture in `credits`.

**Measured** (`node tools/bin/commons-supply.mjs`, free, no key, no model):
12 of 12 real briefs have at least one openly licensed candidate on Commons,
median 11 each, 108 in total. Getting there needed three corrections that only
measuring could have found — the full artist brief returns ZERO for eleven of
twelve, the brief must be cut to its SUBJECT at participles ("showing", "with",
"used") but NOT at prepositions ("leaf" finds a hedge, "leaf in cross section"
finds twelve), and "No restrictions" is a real licence value.

The same measurement produced the best argument for the verifier: **"mature
neuron" returns "Mature cystic teratoma of ovary"** as its top openly licensed
hit — the armoured-tank failure `icons.ts` exists to stop, one subject along.

**Switched on the same evening.** This paragraph read "**Not switched on.**
`prepareLiveClass` takes `web` and nothing passes it" when it was written at
19:39 (`470c666`). Three hours later `4e3d3da` put the default inside
`prepareLiveClass` itself — `liveClass.ts:256` supplies `PICTURE_SEARCH` unless
the caller says `web: null` — rather than in its callers, because a default a
call site has to remember is a rung that quietly stops existing the first time
one is rewritten, which is exactly what a review had already found here.
Nothing outside a test passes `web: null`.

**The verifier was measured before it was switched on, not after.** Sixteen
briefs written the way the planner really writes them, every openly licensed
candidate shown to a Flash model, through the shipped decision functions
(`tools/bin/webrig-verify.mjs`, reported by `webrig-report.mjs`). Six briefs
got a picture. Of twenty-five candidates judged, nineteen were refused as the
wrong thing — a urinary-system chart asked for a kidney, an ovarian teratoma
asked for a neuron, a dowsing pendulum asked for a physics one — and six as
textbook plates with the labels already printed on them, which is the job the
tutor does herself. Not one wrong picture reached a board. That shape is the
right one: photographs of minerals, apparatus, places and specimens are found,
and diagrams were never this rung's job.

The cost half of the argument reversed, and it no longer decides anything. It

**Where a class's money actually goes**, which is what corrected 6.4 and 6.6.
One class was measured against the deployed relay on 2026-09-13, 38 calls, and
`node tools/measure/model-cost.mjs` re-runs the arithmetic. Of a ₹9.90 cached
class: narration TTS ₹5.11 and her spoken replies ₹3.40, so ₹8.51 of TTS, 86%
of the bill; the ear ₹0.27, which takes speech to 89%; judge and cross-question
LLM the remaining ₹1.13, 11%. Every figure there is measured except the ₹3.40,
which is DERIVED from her measured reply tokens at four characters a token —
the harness spoke the eighteen narration lines and not her replies, which the
real classroom speaks on every judged answer (`ClassRoom.tsx:704`). Speech is
also the only line paid in cash, because the models run on Aarav's Cloud
credits.

So caching is a small lever twice over. It discounts prompt tokens only, and
the judge's whole prompt side is ₹0.176 of that ₹1.13 (2,460 tokens over 8
calls); the rest is output and thinking, which caching does not touch. The
brain then got cheaper without it, six hours after the measurement: `ced4610`
(2026-09-13) set the judge to `effort: 'none'`, measured over 72 probe answers
at 31% cheaper with all 72 verdicts unchanged, so the live judge is about
₹0.78, a cached class about ₹9.55 and the brain about 8%.

The lever that moves the rest is self-hosting the voice — `tools/speech`, Piper
at 10.8x realtime, 355 ms to the first line against the vendor's 360 ms,
measured 2026-09-14 — which would take ₹8.51 off a ₹9.90 class and give 6.6 its
₹23/student-hour base. CONDITIONAL, and not in effect: it needs a Piper voice

## What verifying found that planning did not

Running `/code-review` on my own work three times, over ten commits, found
**23 real defects**. Several were in code written minutes earlier to fix an
earlier finding. Four are worth carrying forward as classes of mistake:

1. **A patch script's replacement string expands `$&`.** It wrote
   `'\\export function saveable('` into a regex escape, so a student called
   "Md. Arif" made `new RegExp` throw — inside a call nobody awaited, so the
   class was silently never saved. Every replacement is a function now.
2. **A blank `VITE_` variable is the empty string, not undefined.** `??` keeps
   it, so with the blank line this repo ships every analytics event posted to
   the app's own origin and vanished.
3. **A fix can create the next bug.** `speakSafely` returned void, so its
   callers carried on straight over the helpline message it had just
   substituted — the same failure the `halt` flag had been added to prevent one
   commit before.
4. **Rollup's chunking is a heuristic, not a contract.** One small module
   imported by both the entry and a lazy route merged 406 kB of outcome maps
   into the first download: 129 kB gzipped to 200. It is a named chunk now.

And three from the morning, still worth keeping:
