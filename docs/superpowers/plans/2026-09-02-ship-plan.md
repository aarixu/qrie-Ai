audit instead of around the plan. The plan is Aarav's and it predates the

**Sources.** The phases are Aarav's, stated 2026-09-02. The architecture is

## SETTLED — do not re-open

These were decided with evidence and are not open questions. Writing them down
because one of them was re-opened by me on 2026-09-02, which cost an hour.

| Decision | When | Why it stands |
|---|---|---|
| **Gemini direct** for the brain, with NCERT context caching | 2026-08-30 | Build order item 4. OpenRouter was always the stopgap. |
| **On-device STT and TTS** | 2026-08-30 | The whole ₹1.41/student-hour case is client-side offloading. Cloud speech is temporary scaffolding, so which cloud vendor it uses is not worth arguing about. |
| **STT must be multilingual** | 2026-08-31 | Moonshine is English-only and these students speak Hinglish. Measured: an English-only model returned eight words from twelve minutes. |
| **Synthesise during prep, never live** | 2026-08-31 | Measured 0.7x realtime on a 4 GB Mali phone. |
| **Models bundled in the app** | 2026-08-30 | Kills the 255 MB first download; warmed at app start while the student picks a topic. This is why Phase 2 must come before Phase 3. |
| **2D Rive avatar** | 2026-08-30 | 250 KB against 4.5 MB, and no uncanny valley. The code-drawn penguin holds the seam until a .riv exists. |
| **The recording is a SPINE, not a session** | 2026-08-29 | Narration plus canvas actions are cached; the live tutor fills the personal parts per student. |
| **Duolingo-school UI, not invented** | earlier | Copy established edtech language. |

### B2 — Supabase CLI
1. `npm install -g supabase`
2. `supabase login` → browser opens → **Authorize**
3. `supabase link --project-ref ueemqirxyrltdmqgnidy` → it asks for the
   **database password** from when you created the project

### B3 — Edge Function secrets
```
supabase secrets set OPENROUTER_API_KEY=<new key>
```
SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY are supplied by
Supabase itself — do not set those.

### B11 — Allow anonymous sign-ins (one toggle, and nothing works without it)
1. **supabase.com/dashboard** → project → **Authentication → Sign In / Up**
2. Find **Allow anonymous sign-ins** → turn it **on** → **Save**

Why: the relays refuse anyone they cannot name, because behind each one is
your OpenRouter balance. Anonymous sign-in gives every phone a real account
from the first launch, so a student who has not signed up still gets classes
and still gets metered — and the day they sign in with an email, it is the
same account rather than a new one.

### B12 — The ticket secret, then deploy
1. Make a long random string. Any of these works:
   - macOS/Linux: `openssl rand -base64 48`
   - Windows PowerShell: `[Convert]::ToBase64String((1..48|%{Get-Random -Max 256}))`
2. `supabase secrets set RELAY_TICKET_SECRET=<that string>`
3. `supabase functions deploy relay --no-verify-jwt`

`--no-verify-jwt` is required and is not a hole: the platform's own check
would reject the speech request before our code sees it, and that request
cannot carry an Authorization header — it is an `<audio>` element, which is
what makes her voice start in a third of a second instead of two and a half.
Every route checks the caller itself.

4. Tell me the function URL and I set `VITE_RELAY_URL`.
5. Run the new migration: `supabase db push` (this creates `relay_usage` and
   `claim_relay`, which is what the daily budget actually counts in).

### B4 — Is RLS actually on?
1. **supabase.com/dashboard** → project → **Table Editor** → `student_state`
2. Top right should read **RLS enabled**. If it says *disabled*, every student
   can read every other student's rows.
3. If disabled: **SQL Editor → New query** → run:
   ```sql
   alter table student_state enable row level security;
   create policy "own rows" on student_state
     for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
   ```
4. Tell me which it said.

### B13 — Crash reporting and analytics (free, five minutes)
1. **sentry.io** → sign up → **Create Project** → platform **React** →
   **Settings → Client Keys (DSN)** → copy the DSN (it looks like
   `https://abc123@o42.ingest.sentry.io/7654321`)
2. **posthog.com** → sign up → pick the **EU** region → **Project Settings →
   Project API Key** → copy the one starting `phc_`
3. Send me both, or paste them into `apps/classroom/.env.local`:
   ```
   VITE_SENTRY_DSN=<the DSN>
   VITE_POSTHOG_KEY=phc_<the key>
   ```

Both of those are PUBLIC keys — they can only send data in, never read it out,
which is why they may sit in a browser bundle. Do not use a "personal API key"
from either service; those can read, and those are secrets.

Nothing about a student goes to either one: no transcript, no typed doubt, no
answer, no name, no email, and not their account id. Crashes and events are
grouped by a random number generated on the phone.

## What verifying found that planning did not

Running `/code-review` on my own work three times, over ten commits, found
**23 real defects**. Several were in code written minutes earlier to fix an
earlier finding. Four are worth carrying forward as classes of mistake:

1. **A patch script's replacement string expands `$&`.** It wrote
   `'\\export function saveable('` into a regex escape, so a student called
   "Md. Arif" made `new RegExp` throw — inside a call nobody awaited, so the
   class was silently never saved. Every replacement is a function now.
2. **A blank `VITE_` variable is the empty string, not undefined.** `??` keeps
   it, so with the blank line this repo ships every analytics event posted to
   the app's own origin and vanished.
3. **A fix can create the next bug.** `speakSafely` returned void, so its
   callers carried on straight over the helpline message it had just
   substituted — the same failure the `halt` flag had been added to prevent one
   commit before.
4. **Rollup's chunking is a heuristic, not a contract.** One small module
   imported by both the entry and a lazy route merged 406 kB of outcome maps
   into the first download: 129 kB gzipped to 200. It is a named chunk now.

And three from the morning, still worth keeping:

5. **The audit was right about the icons and wrong about the fonts**, and I
   repeated its error before checking. The real defect was worse: no Devanagari
   in any of the three families, so every Hindi word fell to a system font.
6. **The biggest performance win was free.** `Viewport` re-exported from the
   stage barrel dragged three.js into every bundle for a feature no lesson uses.
7. **A test that names one file checks one file.** The guard on the map's
   lesson references said `class10-science` explicitly, so the two Class 9 maps
   were never checked — and they held 175 references to lessons that had never
   existed.
